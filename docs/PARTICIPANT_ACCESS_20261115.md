# Вход участников: frontend от 15 ноября 2026

Исправлена потеря `secure_login_required`: форма PIN теперь действительно переключается на email/пароль/2FA. Сессия, полученная при входе или активации приглашения, проверяется сервером до замены предыдущей сессии. При временном сетевом сбое существующая сессия сохраняется.

Приложение `/app/` сначала проверяет сохранённую сессию серверным `status` и только затем открывает кабинет. Просроченная сессия удаляется; привилегированная направляется к защищённому входу. Старый профиль не восстанавливается из общего локального кэша. При смене сессии/профиля очищаются старые персональные кэши; ID владельца кэша сверяется с подтверждённым сервером игроком.

Добавлены таймауты запросов входа, сообщения о временной блокировке и устаревшем PIN, обработка сетевой ошибки проверки приглашения и безопасный разбор его fragment. Данные мира и текущего участника загружаются параллельно. Версии JS и service worker обновлены согласованно.

Проверка: `node --test tests/participant-access.test.cjs` — 9 тестов; `node --check app/js/app.js` и `node --check app/sw.js` проходят. Тесты исполняют JavaScript с подменёнными DOM, localStorage и fetch; это не проверка в реальном браузере или production. Реальным участникам сообщения не отправлялись.

Ветка не опубликована на рабочем сайте. В `HANDOFF.md` есть требование подтверждения production-деплоя. Перед выпуском сверить действующую версию сайта, выпустить backend из связанного PR в `dank00-arch/TRIZNES`, затем эти файлы. Не использовать полный инфраструктурный deploy-скрипт для небольшой правки входа: он также затрагивает сервис сообщений и nginx. Проверить обычный и защищённый вход, приглашение, истёкшую сессию, смену пользователя и обновление установленного PWA.
