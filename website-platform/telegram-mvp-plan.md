# ТРИЗНЕС: OAuth и Telegram MVP-план

## Почему мы меняем регистрацию

Сейчас форма регистрации в сайте вызывает Supabase Auth напрямую из браузера. Это связано сразу с несколькими зависимостями: Auth, таблица profiles, email confirmation, RLS, роли и лимиты. В результате регистрация ломается не потому, что пользователь заполнил форму неправильно, а потому что на уровне инфраструктуры нет стабильной точки создания аккаунта.

Для запуска проекта правильнее сделать Telegram-бот точкой регистрации, а сайт — интерфейсом уже созданного профиля.

## Архитектура MVP

### 1. Telegram-бот
Бот отвечает за регистрацию и сбор данных пользователя:
- /start
- выбор роли: персонаж, ангел-инвестор, сообщество
- сбор полей:
  - псевдоним
  - телефон
  - email
  - согласия
  - код персонажа, если нужен
- сохранение данных в Supabase
- отправка ссылки на сайт

### 2. База данных
Используем Supabase, в котором лежат таблицы:
- profiles
- consents
- user_data
- communities
- locations

### 3. Сайт
Сайт перестаёт создавать аккаунты самостоятельно. Он:
- берёт telegram_user_id из Telegram WebApp или параметра URL
- делает запрос к API
- получает профиль пользователя
- показывает интерфейс проекта под этим пользователем

## Сценарий регистрации в боте

1. Пользователь запускает бота.
2. Бот приветствует и предлагает роль.
3. Пользователь выбирает роль.
4. Бот задаёт вопросы по шагам.
5. Бот собирает все данные и проверяет согласия.
6. Бот создает запись в profiles.
7. Бот создает запись в consents.
8. Бот создает запись в user_data.
9. Бот отправляет ссылку на сайт с идентификатором пользователя.

## Параллельная схема для сайта

### Endpoint: GET /api/profile?telegram_user_id=...
Возвращает профиль пользователя.

### Endpoint: POST /api/register
Принимает:
- telegram_user_id
- username
- first_name
- last_name
- phone
- email
- role
- character_code
- consents

## Важные правила

- Bot token хранится только на сервере.
- Нельзя хранить токен в HTML или JavaScript.
- Сайт не должен создавать аккаунты напрямую.
- Разрешения на таблицы должны быть минимальными и понятными.

## MVP-порядок работ

1. Создать SQL-таблицы.
2. Подключить Telegram-бота.
3. Реализовать сценарий регистрации в боте.
4. Добавить API получения профиля.
5. Подвязать сайт к API.
6. Проверить: бот -> база -> сайт -> профиль виден.

## Итог

Для ТРИЗНЕС правильная стратегия запуска — Telegram как точка регистрации, а сайт как интерфейс профиля и экосистемы. Это устраняет зависимость от прямой frontend-регистрации, которая сейчас ломается по архитектурным причинам.
