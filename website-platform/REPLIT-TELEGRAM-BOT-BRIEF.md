# Задание для Replit: регистрация ТРИЗНЕС через Telegram

Нужно развернуть Telegram polling-бот ТРИЗНЕС в Replit и подключить его к API платформы `https://triznes.online`. В Replit запускается только `bot.js`; `server.js` и service-role secret остаются на backend платформы. Не переписывай сайт и не меняй несвязанные функции.

## Исходники для загрузки в Replit

Загрузить архив `TRIZNES-telegram-bot-for-Replit.zip` и распаковать его в корень Replit-проекта. В архиве файлы уже расположены в корне:
- `bot.js` — текущий Telegram-бот и анкета.
- `server.js` — API endpoint для загрузки анкеты по одноразовому коду.
- `package.json` — зависимости и команды.
- `README.md` — текущая схема настройки и запуска.
- `.env.example` — только названия переменных, без реальных значений.
- `supabase-migration-20261002-telegram-registration-gate.sql` — таблица кодов и обязательная проверка кода при создании аккаунта.
- `supabase-migration-20261002-telegram-registration-handoff.sql` — создание связанного с Telegram профиля и сохранение анкеты.

Контекст интеграции сайта: `index.html` запрашивает `POST /api/telegram-registration/draft`, подставляет ответы и код в регистрацию Supabase Auth. Бот вызывает `POST /api/telegram-registration/submit`, проверяет готовность через `GET /api/telegram-registration/status` и погашает старую ссылку через `POST /api/telegram/link/consume`. Не запускать `server.js` в Replit и никогда не добавлять в Replit `SUPABASE_SERVICE_ROLE_KEY`.

## Текущий задуманный поток

1. Участник запускает бота командой `/start`.
2. Бот показывает философию проекта, ссылки на 3 вводных видео и песню, затем просит выбрать точку на карте Сочи как первое простое задание.
3. Бот предлагает роль: зритель, персонаж, поддержка заданий, ментор или площадка/сообщество.
4. Для роли «Персонаж» запрашивает отдельный 4-значный код доступа.
5. Бот собирает псевдоним, телефон, email, краткий рассказ о себе, мечту, навыки и желаемое развитие.
6. Бот передаёт анкету на `POST /api/telegram-registration/submit` по HTTPS с `Authorization: Bearer <TELEGRAM_REGISTRATION_API_SECRET>`. Backend сохраняет анкету и SHA-256 хэш случайного 6-значного кода в `telegram_registration_codes`, срок кода 30 минут; сам код показывает участнику.
7. Сайт получает анкету по коду через backend. На сайте пользователь задаёт пароль и подтверждает юридические согласия.
8. Триггер Supabase проверяет совпадение email/полей анкеты, одноразово погашает код, создаёт профиль с Telegram ID, сохраняет ответы и удаляет регистрационный код из Auth metadata. Регистрация без валидного Telegram-кода должна оставаться закрытой.
9. После подтверждения email и входа на сайте `onboarding_status` становится `registered`. Бот проверяет `GET /api/telegram-registration/status?telegram_user_id=...` с тем же Bearer secret. Только ответ `registered: true` разрешает переход на второй уровень.

## Что нужно сделать

- Сначала изучить приложенные исходники, сохранить совместимость существующих endpoint, JSON-полей и SQL миграции.
- Настроить в Replit постоянный worker/Deployment для polling-бота. Backend Express уже обслуживает API платформы; Replit не должен запускать его копию.
- Добавить корректное восстановление/сохранение незавершённых сессий между перезапусками. Сейчас `userSessions` хранится только в памяти и теряется при рестарте; не хранить в открытом виде лишние чувствительные данные. Предложить минимальное безопасное решение, совместимое с Supabase, либо явно описать остаточный риск.
- Проверить вводы, обработку повторных/истёкших кодов, ограничения частоты запросов, ошибки Telegram/Supabase и поведение при повторном `/start`.
- Убедиться, что таблица доступна только `service_role`, код одноразовый, а ответы анкеты нельзя получить без действительного кода. Не ослаблять SQL gate и не принимать отметку об оплате из браузерного редиректа.
- Настроить только Replit Secrets: `TELEGRAM_BOT_TOKEN`, `PUBLIC_SITE_URL`, `TRIZNES_BACKEND_URL` и `TELEGRAM_REGISTRATION_API_SECRET`. Secret должен совпадать с секретом на API платформы. Supabase URL/service-role key остаются только на платформенном backend. Не просить публиковать значения в чате и не коммитить их.
- Учитывать, что сайт ожидает API под `/api/` или `window.TRIZNES_BACKEND_URL`; описать точную настройку URL и HTTPS/CORS.
- Добавить/запустить focused tests или проверки для генерации/погашения кода и `/api/telegram-registration/draft`; не подключаться к production базе тестовыми данными.
- В конце предоставить список изменённых файлов, команды запуска, нужные Replit Secrets, SQL шаги в Supabase, deployment тип и недостающие решения. Не выкатывать production и не менять production данные без отдельного подтверждения владельца.

## Важные продуктовые ограничения

- Пароль и юридические согласия собираются только на сайте, не в Telegram.
- Telegram-код регистрации не является 4-значным кодом входа персонажа.
- Не выдавать второй уровень до подтверждённого входа на платформе; не пересылать пароли или service-role ключи в Telegram.
- LUBICOIN — игровые баллы без вывода в рубли.
- Не добавлять обещания дохода/инвестиций и не объединять Black Card с пакетами площадок.
