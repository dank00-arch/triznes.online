# План сборки TRIZNES LIFE GAME + DIRTY PARADISE

## Правило оптимизации
Одна общая модель сущностей и событий; сценарии — данные, а не отдельные реализации. Один вертикальный срез за раз. Существующие Supabase auth, RLS, API, game core и карта — источники истины. Не создавать дублей и не переписывать рабочие контуры без аудита.

## Этап 0 — ядро и сценарий (выполнен в этой ветке)
- Сведены манифест, словарь, шесть глав, квестовый каталог, карта, медиа-стандарты и DIRTY PARADISE.
- Проведён read-only аудит Supabase.
- Подтверждён существующий 13-уровневый `creator_path_v1`; 4 акта DIRTY PARADISE отображаются на те же уровни.
- Создан PR #36, без merge/deploy.

## Этап 1 — runtime audit UI/security
- Проверить текущие UI-вызовы `triznes-game-core` и map data adapter.
- Получить определения RLS policies и RPC для life events, AR layers и map features.
- Проверить edge functions, которые уже создают world/AR events.
**Выход:** точная матрица «экран → API → таблица → permission → событие».

## Этап 2 — единый квестовый вертикальный срез
- Не создавать новый game engine: использовать существующие actions `status`, `daily_quest`, `complete_daily`, `submit_proof` и текущие XP/level-up RPC.
- Сопоставить Q001 «Назови свой импульс» с реальной механикой существующего уровня 1 (СЛОВО — СТИХОТВОРЕНИЕ), не подменяя его произвольным daily quest.
- Пройти ENTRY → APOLLON → CHARACTER → PULT → принять/пропустить → proof → event log.
- Проверить повторный запрос, пропуск, отмену, приватность и доступ другого user_id.
**Выход:** проверенный сквозной игровой путь без фиктивных данных.

## Этап 3 — карта как игровое поле
- Использовать существующие `triznes_world_places`, `triznes_world_map_layers`, `triznes_world_map_features`.
- Сохранить различие REAL POI и ARTISTIC_BRANCH; не считать художественные линии пешеходной навигацией.
- Проверить/добавить координаты только для подтверждённых мест; Villa Poliana и «Мелодия» остаются без GPS-якорей до подтверждения.
- РАЙ/CYBER — два визуальных режима одной карты.
- Проверить RLS, GPS consent, точность, пустые состояния и mobile UX.
**Выход:** реальная карта, подтверждённые POI и один безопасный маршрут.

## Этап 4 — Prompt-to-AR без нейровидео
- Сначала найти существующий route/function и разрешённые способы записи в `sochiwood_life_events` / `sochiwood_ar_layers`.
- Three.js/WebXR compositor + fallback screen-space overlay.
- Allowlist из 5–10 простых AR-ассетов.
- Чат → LLM → JSON Schema → permission/safety gate → AR event.
- Не публиковать AR-событие без проверки consent_ar и видимости.
**Выход:** команда из чата вызывает объект в видоискателе; измеряется p50/p95 latency.

## Этап 5 — V2V тестовый контур
- Отдельный GPU worker и WebRTC gateway; Supabase не проксирует кадры.
- Сначала один стиль Cyber Night на низком разрешении.
- Измерять p50/p95 latency, FPS, frame drops, GPU memory, identity consistency.
- Адаптивный noise controller; reset на оригинальный поток при деградации.
- Не обещать real-time до прохождения тестов на целевых устройствах/сети.
**Выход:** ограниченный live V2V test, не production по умолчанию.

## Этап 6 — полный сезон DIRTY PARADISE
- Подключить 4 акта как сценарные данные на существующие 13 уровней.
- Пять Проводников — подтверждённые персонажи/образы с согласиями.
- Маршрут, события, AR-глифы, музыкальная сцена, трейлер.
- Пилотная сессия в доступных общественных местах.
**Выход:** воспроизводимая игровая сессия, не дублирующая XP/level-up.

## Этап 7 — расширение и качество
- Авторские квесты, сообщества, PULT, архив и Neurofarm.
- Аналитика качества без рейтинга личности.
- Регрессионные тесты на права доступа, согласия, маршруты, мобильные браузеры и происхождение медиа.

## Приоритеты
P0: UI/security audit существующего runtime.
P1: один сквозной квест на текущем game core.
P2: актуализация карты и подтверждение маршрута.
P3: Prompt-to-AR через существующие AR entities.
P4: live V2V GPU worker.
P5: полный сезон DIRTY PARADISE.

## Критерий «готово»
Функция считается реализованной только после проверки работающего пути, тестов, прав доступа и фактического результата в целевой среде. Документация/макет/commit не равны production deployment.
