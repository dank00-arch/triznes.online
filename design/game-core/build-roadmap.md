# План сборки TRIZNES LIFE GAME + DIRTY PARADISE

## Правило оптимизации
Одна общая модель сущностей и событий; сценарии — данные, а не отдельные реализации. Один экран/модуль за раз. Не переписывать существующие auth, API, Supabase или карту без аудита и тестов. Не создавать дублирующие таблицы, если текущие сущности покрывают задачу.

## Этап 0 — фиксация ядра (этот пакет)
- Свести манифест, словарь, главы, квесты, карту, медиа-стандарты и DIRTY PARADISE.
- Утвердить термины и границы между глобальной игрой и сценарием.
- Получить исходный сценарий и дополнительные файлы пользователя; обновить только затронутые документы.

## Этап 1 — аудит реального runtime
- Проверить действующие Supabase таблицы: platform_players, apollon_player_game_state, triznes_daily_quests, triznes_player_proofs, apollon_game_events, triznes_character_artifacts.
- Проверить наличие/состояние quest_nodes, quest_triggers, quest_transitions, locations.
- Проверить Edge Functions, RLS, auth identity, текущие map data и события.
- Сверить ветки UI и активные PR; никаких production writes.
**Выход:** карта соответствия «концепт → существующая сущность/API → пробел».

## Этап 2 — единый квестовый вертикальный срез
- Один квест Q001 «Назови свой импульс».
- Пройти ENTRY → APOLLON → CHARACTER → PULT → accept → complete → event log.
- Проверить повторный запрос, пропуск, отмену и чужой user_id.
- Подключить реальные места только после гео-проверки.
**Выход:** один работающий квест без фиктивных данных.

## Этап 3 — карта как реальное игровое поле
- MapLibre GL + OpenFreeMap как текущая базовая архитектура.
- Реальные координаты POI из проверенного источника.
- Режимы РАЙ/CYBER — визуальные слои одной карты.
- Фильтры люди/события/съёмки/сообщества/места/истории.
- Проверить RLS, GPS consent, точность, пустые состояния и мобильный UX.
**Выход:** один подтверждённый маршрут и выбранная сцена.

## Этап 4 — Prompt-to-AR без нейровидео
- Камера и WebXR/Three.js compositor.
- Allowlist из 5–10 простых AR-ассетов.
- Чат → LLM → JSON Schema → permission gate → AR event.
- Рабочий fallback для браузеров без WebXR: screen-space overlay.
**Выход:** команда из чата вызывает объект в видоискателе с измеримой задержкой.

## Этап 5 — V2V тестовый контур
- Отдельный GPU worker и WebRTC gateway.
- Сначала один тестовый стиль Cyber Night, низкое разрешение.
- Измерять p50/p95 latency, FPS, frame drops, GPU memory, identity consistency.
- Адаптивный noise controller; reset на оригинальный поток при деградации.
- Не обещать real-time до прохождения тестов на целевых устройствах/сети.
**Выход:** ограниченный тестовый live V2V, не production по умолчанию.

## Этап 6 — DIRTY PARADISE сценарий
- Подключить 4 акта/13 уровней как данные сценария.
- Пять Проводников — реальные подтверждённые персонажи/образы.
- Маршрут, события, AR-глифы, музыкальная сцена, трейлер.
- Пилотная съёмка в доступных общественных местах.
**Выход:** воспроизводимая первая игровая сессия.

## Этап 7 — расширение и качество
- Авторские квесты, сообщества, PULT, архив и Neurofarm.
- Сборка аналитики качества без рейтинга личности.
- Регрессионные тесты на права доступа, согласия, маршруты, мобильные браузеры и происхождение медиа.

## Приоритеты
P0: согласованная модель + аудит runtime.
P1: один сквозной квест и event log.
P2: настоящая карта и один маршрут.
P3: Prompt-to-AR.
P4: live V2V.
P5: полный сезон DIRTY PARADISE.

## Критерий «готово»
Функция считается реализованной только после проверки работающего пути, тестов, прав доступа и фактического результата в целевой среде. Документация/макет/commit не равны production deployment.
